01 · Read this first

One system, four layers of capability.

GTM AI is an intent-to-outcome system for account-based marketing. Sales teams define target accounts; the system scores them by ICP matching and buying intent, segments them automatically, researches them intelligently, and personalizes outreach. Everything is measured.

03 · Four-layer model

Complete system architecture

GTM AI is organized into four layers: Data Foundation, Intelligence, Automation, and Measurement.

Layer 1: Data Foundation

Input: Account data from CSV, Salesforce, or HubSpot. Output: Normalized account records. Role: Single source of truth for account attributes (company name, industry, size, revenue, location, founded date).

Layer 2: Intelligence

Input: Normalized accounts. Output: ICP score (0-100), Intent score (0-100), Segment assignment. Role: All scoring logic and segmentation rules live here. This layer is reused by dashboard, CRM integration, and research agent.

Layer 3: Automation

Input: Scored and segmented accounts. Output: Research briefs, personalized email/LinkedIn, A/B test variants, CRM field updates. Role: Research agent (Claude API), personalization engine, and CRM connectors consume Layer 2 scores and generate action.

Layer 4: Measurement

Input: Outreach events (email sent, demo booked, proposal won). Output: ROI per segment, cost-per-acquisition, A/B test statistical significance, conversion funnels. Role: Track what actually worked. Close the loop.

05 · Research & Personalization

Claude AI integration layer

When sales teams need intelligence beyond the numbers, the Research Agent uses Claude API to generate insights, talking points, and personalized outreach.

Research Agent

Generates: Research briefs (company overview + market context), Talking points (conversation starters), LinkedIn messages (personalized), Email variants for A/B testing. Falls back to demo responses when API unavailable.

Personalization Engine

Generates: Email subjects (segment-aware), Email bodies (customized by company profile), LinkedIn DMs (context-rich). A/B variant creation for testing multiple angles.

Claude API Contract

All Claude calls respect a shared account context (ICP score, intent score, segment, buying signals) so the LLM has consistent frame of reference across different output types.

06 · CRM Integration

Salesforce and HubSpot connectors

GTM scores sync back to your CRM as custom fields so your team sees the scores in their daily workflow.

Salesforce Connector

Authenticates via OAuth, fetches Account objects, creates 3 custom fields (GTM_ICP_Score__c, GTM_Intent_Score__c, GTM_Segment__c), syncs scores back via REST API. Batch operations + dry-run mode.

HubSpot Connector

Authenticates via private app API key, fetches Companies, creates 3 custom properties (gtm_icp_score, gtm_intent_score, gtm_segment), syncs via HubSpot REST API. Rate-limit aware, batch-capable.

Both simultaneously

Single integration_example.py script can sync to Salesforce, HubSpot, or both in one run. Useful for teams using multiple CRMs or migrating between them.

Integration principle: Syncing is not one-way. The system should check CRM-stored buying signal history and incorporate it into intent scoring over time, creating a feedback loop.
07 · Measurement & ROI

Close the loop

Record what actually happened (demo scheduled, proposal sent, deal won) and calculate ROI by segment.

A/B Testing

Record send/open/click/reply/meeting metrics for two email variants. Calculate rates, engagement scores (0-100), and statistical significance of differences.

ROI Tracking

Log conversion events (contacted, demo, proposal, won). Track costs by category. Calculate: ROI%, payback period, cost-per-acquisition, segment performance.

Feedback Loop

Winning accounts inform ICP model refinement. Buying signals that correlate with won deals become higher-weighted in intent scoring.

10 · Engineering principles

How new work should connect

1
All teams converge on GTM Core scoring. Dashboard, research agent, personalization, and CRM connectors all consume ICP and intent scores from the same model. Do not create separate scoring logic.
2
Evidence is causal. Record why an account was scored this way: which buying signals fired, which ICP factors matched. Never just a score with no provenance.
3
Sample data is first. Before touching a CRM, test locally with the 20 sample accounts. When integration fails, fall back to sample data so the dashboard doesn't go blank.
4
Dry run before write. CRM integration supports dry_run mode. Always test with real credentials but dry run enabled before syncing scores live.
5
Buying signals matter more than ICP alone. A perfect ICP match with no buying signals is less urgent than a mediocre fit with 5 recent signals. Intent should drive urgency.
6
Close the loop. If you don't measure what actually worked (demos booked, deals won, cost-per-acquisition), you can't improve the model.
7
LLM decisions are optional. Use Claude API for research briefs and personalization, but don't require it. Demo responses let the system degrade gracefully if the API is unavailable or over quota.
8
Build thin vertical slices. Prove: pick an account → score it → display it → export it → sync it to CRM. Then add breadth (more accounts, more signals, more integrations).
11 · For engineers and their LLMs

How to use this brief

Use this document as your starting context, then inspect the repository and code to make specific design decisions.

Before proposing a new feature or integration, ask: What layer does this belong in (Data, Intelligence, Automation, Measurement)? Does it reuse GTM Core scoring or create a separate orchestration system? What is the smallest slice I can ship to prove it works without breaking existing features?

Deployment: The complete system (Python code, integration guides, HTML dashboard) is ready for deployment. Dashboard: gtm-ai-system.vercel.app — live on Vercel with real-time updates.
